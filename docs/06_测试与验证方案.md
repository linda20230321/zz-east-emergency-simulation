# 测试与验证方案

基线版本：0.8.1

## 1. 验证层次

1. 静态数据验证：配置结构、数量、ID唯一性和时间顺序；
2. 逻辑验证：总量守恒、设备状态机、四向出口与路径方向一致性；
3. 界面验证：关键事件可达、三层同图、底图可平移缩放、设备可查询、路线可见、监控窗可拖拽折叠；
4. 性能验证：帧率、刷新、跳转、内存和48小时稳定性；
5. 专家验证：流程符合应急脚本、组织策略合理、输出可解释。

## 2. 当前自动化验证

执行 `npm test`，检查：

- 初始区域人数之和等于37,000；
- 15个事件严格递增，覆盖09:00—09:47；
- 设备配置采用3.0结构，仅包含闸机、广播、信息屏、通道、窗口和6个监控点；
- 15个节点均包含流程、岗位职责和设备操作，关键广播、导向及G806/G1808/G51文案可检索；
- 6个监控点均明确标识为未接入真实视频的仿真占位源；
- 总体布局底图被集成且界面不存在楼层标签切换；
- 总图视口隐藏滚动条，底图框横向100%铺满背景区域，默认110%仅缩放底图内容，并具备拖拽、缩放、复位和监控面板折叠控制；
- 关键步骤聚焦大图、路径推荐独立侧栏、气泡边界拖拽与关闭续播结构完整；
- 正南、正北、西南、西北四条候选路径齐全，并在不同客流阶段切换推荐；
- 数据库包含快照、指标、设备日志、一致性检查、需求追溯和变更记录；
- 版本号和核心文档同步；
- 动态数字看板包含客流预判、积压、晚点、停运、趋势线和数值刷新机制；
- CPU KDE算法、人员矩形显示范围、四色阈值和六路监控同源快照结构完整；
- Web主图不包含KDE网格、区域多边形、密度标签或图例，并包含各层人数与站台乘车联动；
- 生产构建成功。

## 4. 生产版性能试验

标准配置需记录：平均/1%低帧率、峰值内存、CPU/GPU占用、热力端到端延迟、时间跳转P95、设备刷新P95、数据库写入P95、丢帧/缺快照率。测试规模至少包括10k、20k、40k个体或等价LOD，并执行48小时稳定性试验。

## 5. 实验效能指标

- 疏散完成时间；
- 峰值密度及持续时间；
- 超阈值区域数量和累计暴露人分钟；
- 平均/95分位通行时间；
- 队列峰值与清空时间；
- 路径切换次数与绕行代价；
- 设备响应延迟和规则冲突数；
- 方案相对基线的改善率及置信区间。

## 6. 验收证据

每次正式验收保存代码版本、配置版本、随机种子、运行参数、环境、原始日志、快照、测试报告、缺陷清单和签字记录。任何仅凭截图而无运行批次与数据校验和的结果，不作为论文或专利证据。
