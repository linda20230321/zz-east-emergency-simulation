# 应急演练脚本要素映射说明

基线版本：0.8.1

## 1. 映射口径

系统以演练脚本为业务时序依据，当前版本仅保留路径生成与推荐、人员流动状态、视频监控与底图同步相关内容，以及支撑这些流程的闸机、广播、信息屏、通道和窗口。`lib/scenario-script.ts`保存“时间—地点—流程—岗位—设备—操作—展示内容”关系，`lib/simulation.ts`转换设备状态，`lib/dynamic-routing.ts`生成路线与推荐。

底图、流程、配置和统计使用同一精简口径。当前配置为20个设备组、21件运行设备和6个监控点，共27个物理点位；不在本轮范围内的类别不进入底图、流程或指标。

## 2. 当前设备数量

| 类型 | 数量 | 映射依据 |
|---|---:|---|
| 进站闸机 | 4 | 西南、西北、正南、正北四向入口状态 |
| 广播设备 | 6 | 32B小区广播、服务台音响和4个便携广播点 |
| 信息屏 | 5 | 正南、正北、服务台、第八售票处和一层西广场 |
| 通道 | 4 | 换乘通道、西广场疏散通道和左右绿色通道 |
| 退改签窗口 | 2 | 第八售票处50、51号窗口 |
| 监控点 | 6 | 四向出口、二层换乘通道和一层西广场 |

## 3. 四向路线与出口

| 路线 | 出口方向 | 起终点 | 动态依据 |
|---|---|---|---|
| EVAC_SW | 西南 | 候车室—西广场 | 曼哈顿距离、路径长度、实时密度、转向代价 |
| EVAC_S | 正南 | 候车室—西广场 | 曼哈顿距离、路径长度、实时密度、转向代价 |
| EVAC_N | 正北 | 候车室—西广场 | 曼哈顿距离、路径长度、实时密度、转向代价 |
| EVAC_NW | 西北 | 候车室—西广场 | 曼哈顿距离、路径长度、实时密度、转向代价 |

四条路线同时生成并显示。仿真每次刷新均读取当前客流密度，重新计算综合代价并更新推荐；疏散人员沿推荐路线和备选路线移动，推荐变化会同步到六路监控。

主界面底图仅显示路线与方向箭头，不叠加“疏散线 候车室—西广场”文字框或路径推荐卡。关键步骤聚焦大图在底图外侧栏显示路线推荐；底图内容默认110%缩放，底图框横向铺满背景区域，外部UI不随底图缩放。

## 4. 六路监控对应关系

| 监控 | 对应位置 | 同步内容 |
|---|---|---|
| CAM-01 | 西南疏散通道 | 人员流动、密度和推荐状态 |
| CAM-02 | 正南疏散通道 | 人员流动、密度和推荐状态 |
| CAM-03 | 正北疏散通道 | 人员流动、密度和推荐状态 |
| CAM-04 | 西北疏散通道 | 人员流动、密度和推荐状态 |
| CAM-05 | 二层换乘通道 | 四路客流下行汇合状态 |
| CAM-06 | 一层西广场 | 疏散到达人数和实时承接状态 |

六路画面均为明确标识的仿真源，不冒充真实视频。所有画面按`regionIds`采样主图同一Agent快照，同时读取`computeDynamicRoutes`的推荐结果和统一仿真时钟。

## 6. 可验证方式

1. 点击15个时间节点，核对当前流程、岗位职责和设备操作；
2. 在09:21—09:35连续播放，确认四条路线同时显示且推荐随密度变化；
3. 点击底图设备，核对名称、位置、数量、责任人、状态和脚本节点；
4. 打开六路监控，核对人员位置、人数、路线推荐和仿真时刻与底图一致；
5. 在09:35—09:46核对G806、G1808、G51三轮放行以及区域人数、路线和设备状态；
6. 执行`npm test`，验证事件、精简设备范围、四向路径、动态推荐、监控同源、数据库和生产构建。

## 7. 数据边界

设备点位和路径节点为总体布局图上的归一化参考坐标，不具备测绘精度。人员数量在脚本锚点之间采用守恒插值；正式实验须使用CAD/BIM路网、视频计数、人工统计或脱敏客流序列校准。
