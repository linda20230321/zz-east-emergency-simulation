# 数据与算法设计

基线版本：0.8.0

## 1. 配置数据

`data/initial_conditions.json` 定义总量、列车和校准锚点；`script_timeline.json` 定义15个事件；`lib/scenario-script.ts` 定义每个节点的流程、岗位、人员、设备动作和脚本文案；`region_config.json` 定义区域和容量；`device_config.json` 定义精简后的设备与6个监控点；`density_config.json` 定义KDE、带宽、显示范围规则、Web圆点呈现策略及四色阈值；`monitor_config.json` 定义6个监控场景、区域绑定、路线状态源和统一Agent数据源；`path_network.json` 定义四向疏散路网及改进型A*参数。配置均带 `schemaVersion`，不允许在不升级版本的情况下破坏字段兼容性。

## 2. 人员模型

生产目标采用微观 Agent FSM：`IDLE → MOVING → QUEUING → WAITING → BOARDING → EXITING`。每个Agent至少包含位置、楼层、区域、目的区域、车次、发车时间、状态、路径、速度、进站资格和信息感知状态。

第一阶段使用聚合圆点进行宏观验证。全局视图每点最多代表50人，最后一点记录余数权重；聚合只影响渲染，不影响区域真实人数统计。每个区域定义百分比矩形显示范围，随机点在扣除圆点安全边距后生成，并在起止点之间插值；底图上不绘制区域多边形、网格或深色椭圆。

## 3. 客流校准曲线

采用分段线性守恒插值连接脚本锚点：09:05总人数37,000；09:35候车厅约18,000；09:46候车厅约20,000。总量在候车厅、周边通道、检票口、售票处、站台和西广场之间转移，任意时刻区域人数之和等于37,000。

生产实验必须使用真实观测序列替换插值曲线，并报告 MAPE、RMSE、峰值时间偏差、区域密度等级一致率和路径方向一致率。

顶部“10分钟站内积压预判”使用同一守恒曲线读取当前时刻后10分钟的站内积压值；“站内积压”定义为候车厅、商业通道、检票口集结区和第八售票处人数之和，不含站台层与一层西广场。变化量以当前值和前1分钟值计算，趋势线按最近5.5分钟、每0.5分钟取样。该结果属于仿真预测，不是接入实时客流数据后的运营预测。

## 4. 路径规划

当前系统从候车室到西广场同时计算西南、正南、正北、西北四条候选路线。`lib/dynamic-routing.ts`以曼哈顿距离作为A*启发函数，并按每个仿真时刻读取候车室、西广场及出口通道密度。综合代价为：

`cost = path_length × (1 + density × 2.85) + turn_penalty`

启发代价使用`Manhattan(current, goal) × 1.08`；边代价融合路径长度、实时密度和转向惩罚。每次状态刷新均重算四条路线，综合代价最低者成为实时推荐；疏散人员位置沿同一批路线插值更新，因此密度阶段变化会同步改变推荐、人员流向和六路监控显示。生产版需把归一化节点替换为CAD/BIM可测量路网，并增加门宽、楼梯能力和队列切换缓冲。

## 5. 密度与热力

区域基准密度为人数/容量。系统在CPU端以同一Agent快照执行高斯核密度估计：按区域带宽计算采样点核函数和，除以区域最大核值获得局部KDE，再与区域基准密度组合并截断至0—1。颜色严格为：`d<0.30 #4CAF50`、`0.30≤d<0.60 #FFEB3B`、`0.60≤d<0.85 #FF9800`、`d≥0.85 #F44336`。为避免遮挡底图，Web v0.8.0不渲染热力网格、密度数值、等级标签和图例，仅以人员圆点颜色反映所属区域密度；CPU结果仍可用于监测、记录和Unity热力接口。

生产Unity实现位于`unity/Runtime/KdeDensityController.cs`和`unity/Shaders/KdeHeatmapOverlay.shader`。控制器按刷新频率生成RFloat密度纹理，Shader采样密度并映射相同阈值。正式实验需通过视频标注或人工计数校准带宽、容量、网格分辨率和刷新频率。

六路监控不再独立随机生成人员，而是按`data/monitor_config.json`中的`regionIds`从统一Agent快照抽样；监控画面显示对应区域统计人数，并使用相同仿真时刻。真实视频接入后，检测结果也必须先写入统一快照，再驱动所有视图。

## 6. 设备状态机

同一设备指令冲突时优先级为：人工安全操作 > 精确时间线事件 > 规则引擎 > 默认状态。所有状态变化必须记录设备ID、仿真秒、旧状态、新状态、触发事件、触发类型和参数。

路线与设备具有强一致约束：关闭的闸机或通道不得进入新路径；四个出口方向与底图罗盘保持一致；09:35—09:46按基础候车、G806、G1808、G51四个连续阶段切换广播、绿色通道和人员流向。

## 7. 一致性不变量

1. 总人数等于区域人数之和；
2. 设备状态属于其状态机允许集合；
3. 事件按 offset 严格递增触发；
4. 人员位置必须位于可通行网络或合法区域；
5. 关联路径关闭时无新Agent进入；
6. 快照总数、区域指标和可视化读数时间戳一致；
7. 任何人工干预均进入审计日志。
