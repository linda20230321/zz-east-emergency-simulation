# 数据与算法设计

基线版本：0.3.0

## 1. 配置数据

`data/initial_conditions.json` 定义总量、列车和校准锚点；`script_timeline.json` 定义15个事件；`region_config.json` 定义区域和容量；`device_config.json` 定义五类39个设备；`monitor_config.json` 定义6个监控点位、仿真源状态和悬浮方式；`path_network.json` 定义8条业务路径。配置均带 `schemaVersion`，不允许在不升级版本的情况下破坏字段兼容性。

## 2. 人员模型

生产目标采用微观 Agent FSM：`IDLE → MOVING → QUEUING → WAITING → BOARDING → EXITING`。每个Agent至少包含位置、楼层、区域、目的区域、车次、发车时间、状态、路径、速度、进站资格和信息感知状态。

第一阶段使用聚合点进行宏观验证。全局视图每点约50人，点数约740；楼层与区域视图预留20人/点和10人/点。聚合只影响渲染，不影响数据库中的真实人数统计。

## 3. 客流校准曲线

采用分段线性守恒插值连接脚本锚点：09:05总人数37,000；09:35候车厅约18,000；09:46候车厅约20,000。总量在候车厅、周边通道、检票口、售票处、站台和西广场之间转移，任意时刻区域人数之和等于37,000。

生产实验必须使用真实观测序列替换插值曲线，并报告 MAPE、RMSE、峰值时间偏差、区域密度等级一致率和路径方向一致率。

## 4. 路径规划

生产算法为分层A*：楼层内图负责水平移动，扶梯/楼梯/电梯节点负责层间转移。边权建议为：

`cost = distance / free_speed × congestion_weight × device_weight × policy_weight`

- 密度≥0.85：拥堵权重5；
- 0.60≤密度<0.85：权重2；
- 闸机/门关闭：无穷；
- 绿色通道：0.5；
- 违反单向规则：无穷；
- 已经进入切换缓冲区的队列先完成通行，再切换状态。

## 5. 密度与热力

第一阶段使用区域人数/容量得到区域密度，并映射四级颜色。生产阶段使用KDE或网格密度估计，带宽必须通过视频标注或人工计数校准。热力刷新与人数统计使用同一时刻快照，避免视觉与数据读数错位。

## 6. 设备状态机

同一设备指令冲突时优先级为：人工安全操作 > 精确时间线事件 > 规则引擎 > 默认状态。所有状态变化必须记录设备ID、仿真秒、旧状态、新状态、触发事件、触发类型和参数。

疏散指示具有强一致约束：指向关闭闸机的标识必须关闭；疏散转回流时箭头方向同步反转；路径关闭后关联标识不得继续显示。

## 7. 一致性不变量

1. 总人数等于区域人数之和；
2. 设备状态属于其状态机允许集合；
3. 事件按 offset 严格递增触发；
4. 人员位置必须位于可通行网络或合法区域；
5. 关联路径关闭时无新Agent进入；
6. 快照总数、区域指标和可视化读数时间戳一致；
7. 任何人工干预均进入审计日志。
