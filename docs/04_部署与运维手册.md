# 部署与运维手册

基线版本：0.3.0

## 1. 当前可运行系统

要求 Node.js 22.13+。在工程根目录执行：

```bash
npm ci
npm run verify:sync
npm test
npm run start
```

`npm test` 会依次执行版本同步校验、生产构建和数据测试。部署前必须全部通过。

## 2. 配置

- 站点部署身份位于 `.openai/hosting.json`，不得复制到其他工程；
- 场景配置位于 `data/`；
- 数据库结构位于 `database/001_schema.sql`，基线数据位于 `database/002_seed_baseline.sql`；
- 运行时秘密不得写入Git或前端文件，应通过部署平台的环境变量/密钥管理注入；
- 任何配置变更需更新 `VERSION`、`package.json`、变更记录、追溯矩阵和测试。

## 3. PostgreSQL/TimescaleDB初始化

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/001_schema.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/002_seed_baseline.sql
```

生产环境使用独立数据库角色：迁移角色可DDL，应用写入角色仅限业务表DML，报告角色只读。每日备份，实验批次完成后生成不可变导出和校验和。

## 4. 发布流程

1. 接收变更并建立 `CR-*`；
2. 更新需求、设计、代码、数据与测试；
3. 运行 `npm run verify:sync` 和 `npm test`；
4. 形成版本说明、追溯矩阵和验收记录；
5. 保存可回滚检查点；
6. 发布并确认服务状态；
7. 记录版本、发布时间、配置校验和和批准人。

## 5. 运行监控

建议监控：页面错误率、事件触发延迟、时间轴跳转延迟、帧率、内存、数据库写入延迟、快照缺失率、总量守恒失败数和设备冲突数。守恒失败、关键事件漏触发、数据库不可写或状态机非法转换应触发阻断级告警。

## 6. 备份与恢复

- 配置和代码通过版本库恢复；
- 数据库使用全量备份 + WAL/时间点恢复；
- 媒体和模型使用对象版本控制；
- 恢复演练至少每季度一次；
- 回滚不得覆盖已有实验结果，失败版本标记为失效并保留审计记录。

## 7. Unity生产版交付补充

生产版需固定 Unity 2022 LTS 小版本、包清单、渲染管线、目标Windows版本、GPU驱动和构建脚本。交付包应包含源码、锁定的依赖清单、自动构建脚本、数据库迁移、配置样例、离线资源、安装/卸载脚本、校验和与第三方许可证清单。
