# 需求基线与范围说明

基线版本：0.3.0  
基线日期：2026-08-29  
场景编号：ZZE-FLOOD-2023-0423

## 1. 资料依据

1. 《因水害影响北京方向列车大面积晚点旅客滞留疏散应急演练脚本4.23》；
2. 《高保真数字化仿真系统技术需求规格书》；
3. 《郑州东站总布局图》；
4. 本工程内 `data/` 的结构化基线配置。

## 2. 当前阶段交付边界

当前版本是“系统构建与文档体系第一阶段基线”，目标是先验证业务逻辑、时间线、客流守恒、设备联动、三层综合态势和数据追溯。已实现可运行的浏览器交互系统，可作为评审、需求澄清、培训演示及后续 Unity 生产版的逻辑参照。

当前版本不冒充最终 Unity 3D Windows 独立程序。Unity DOTS/ECS、真实视频融合、监控人数识别、实测 CAD/BIM 坐标、语音音频、40,000个微观个体压力测试和 Windows 安装包，均需在取得相应源数据和运行环境后进入生产实现阶段。

## 4. 源资料冲突与处理决定

| 冲突/缺口 | 处理决定 | 后续确认 |
|---|---|---|
| 规格书称“14个关键节点”，完整事件表实际列出15个 | 以事件表和脚本为准，采用15个节点 | 需求方确认后修订正式规格书 |
| 9:35回流段称候车厅约18,000人，9:46称约20,000人 | 解释为疏散后回流导致人数回升，建立守恒插值曲线 | 用实测/人工记录校准 |
| 9:46文本写“三小时后”，但时间轴仅到9:47 | 当前按脚本标记09:46处理，“三小时后”列为文本待澄清 | 决定是演练压缩时间还是实际时间 |
| 总布局图为信息图，不是CAD/BIM | 当前坐标仅为归一化参考坐标，禁止用于工程测量 | 补充CAD/BIM、标高、门宽、扶梯能力 |
| 未提供6路监控视频、人数识别结果、音频 | 当前实现6个监控点和明确标识的仿真悬浮画面，不将其表述为真实视频 | 补充媒体及其授权、时钟和区域映射 |
| 脚本附件1为2023占位日期 | 以场景编号固定，日期参数化 | 正式实验前确定日期和列车时刻版本 |

## 5. 数据真实性分级

- A级：脚本明确给出的事实，如37,000人、68列晚点、6列停运、时间节点和车次；
- B级：规格书定义的设计参数，如设备状态机、容量阈值和路径规则；
- C级：为保证连续仿真而建立的工程假设，如中间时刻客流插值、归一化坐标；
- D级：演示数据或占位数据，必须在界面和报告中显式标识，不得作为论文结论。

## 6. 下一阶段准入条件

生产版启动前至少需要：CAD/BIM或可测量平面；6路视频/标注序列；真实或脱敏客流统计；设备接口协议；硬件配置；应急广播音频；专家确认的容量、门宽、通行能力和行为参数；正式验收环境。
