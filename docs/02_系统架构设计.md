# 系统架构设计

基线版本：0.8.0

## 1. 架构目标

系统采用“配置驱动、事件驱动、可重复回放、证据可追溯”的分层架构。第一阶段使用 TypeScript/React 验证交互与业务逻辑；生产阶段可将同一配置协议接入 Unity 2022 LTS + DOTS/ECS。两端共享场景ID、事件ID、设备ID、区域ID、路径ID和数据库模型，避免重新编码业务语义。

## 2. 逻辑分层

| 层 | 组件 | 当前实现 | 生产扩展 |
|---|---|---|---|
| 表现层 | 北向校正的高清三层连续底图、四向出口、四色Agent圆点、四条动态路线、精简设备、6路同源监控窗、流程追溯面板、8项动态数字看板 | React/CSS/SVG 2.5D | Unity 3D、GPU实例化、KDE热力Shader |
| 交互层 | 时间轴、倍速、快捷键、设备查询、总图拖拽缩放、监控窗拖拽及折叠 | 浏览器交互 | Unity Input System、多屏与触控 |
| 仿真层 | 事件队列、守恒客流插值、设备状态机、融合曼哈顿距离与密度的改进型A* | `lib/simulation.ts`、`lib/dynamic-routing.ts` | DOTS/ECS、可测量路网、队列与行为模型 |
| 数据层 | JSON配置、PostgreSQL/TimescaleDB脚本、追溯矩阵 | `data/`、`database/` | 运行时读写、实验批次和时序数据 |
| 治理层 | 版本、变更、测试、需求追溯 | `VERSION`、同步校验、文档体系 | CI/CD、电子签审、发布审批 |

## 3. 核心运行链

1. 读取场景、区域、设备、路径和时间线配置；
2. 以固定随机种子生成或加载初始旅客状态；
3. 时间控制器推进仿真时钟；
4. 事件调度器执行到期事件；
5. 设备状态机和路径网络接收事件动作；
6. 改进型A*按路径长度、实时密度、转向代价与曼哈顿启发值计算四条候选路线；
7. 人员引擎沿推荐路线和备选路线移动，推荐随密度变化动态切换；
8. 区域统计、监控画面与密度计算刷新可视化；
9. 快照、设备日志和一致性校验写入时序数据库；
10. 回放引擎按快照和事件日志重建任意时刻状态。

人员态势采用单一数据链：区域人数生成统一Agent快照；快照同时输入主图人员圆点、CPU KDE计算、监控区域采样、楼层/站台统计和一致性校验。任何视图不得自行生成随机人员。Agent位置由百分比矩形显示范围和圆点安全边距约束；Web端不绘制KDE网格、区域多边形、密度数值或等级标签。

## 4. 标识体系

- 场景：`ZZE-FLOOD-2023-0423`；
- 事件：`E` + HHMM，如 `E0921`；脚本步骤：时间节点加操作对象、责任岗位和原始文案；
- 闸机：`GATE_*`；广播：`BC_*`；信息屏：`DSP_*`；疏散门：`DOOR_*`；窗口：`WINDOW_*`；
- 路径：`EVAC_SW`、`EVAC_S`、`EVAC_N`、`EVAC_NW`；监控：`CAM-01`—`CAM-06`；
- 运行批次：建议 `RUN-YYYYMMDD-HHMM-用途-序号`。

## 5. 状态确定性

每次实验保存引擎版本、配置版本、随机种子、参数集、源数据校验和。相同四元组应生成相同关键状态哈希。人工操作必须写入 `device_event_log`，并拥有高于自动时间线的优先级，防止“演示结果不可复现”。

## 6. 生产版部署拓扑

- 仿真工作站：Unity可执行程序与场景资源；
- 数据服务：PostgreSQL + TimescaleDB；
- 媒体/模型存储：对象存储或内网文件服务；
- 管理与报告：Web管理端或桌面内嵌面板；
- 可选集成：视频分析服务、设备协议网关、身份与权限服务；
- 安全边界：生产、实验、演示环境分离，外部接口采用白名单和只读优先策略。

## 7. 关键设计约束

总体布局图上的设备、监控和路线采用百分比归一化参考坐标，不具备测绘精度；交付底图以北向上为统一方向，显式标注正南、正北、西南、西北出口，页面顶部保留“郑州东站总布局图”标题；任何真实视频、人员画像或设备接口数据不得写入前端静态文件。
