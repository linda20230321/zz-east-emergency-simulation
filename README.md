# 郑州东站应急疏散高保真仿真系统

版本：0.3.0

基于水害导致北京方向列车大面积晚点、旅客滞留疏散演练脚本构建的数据驱动仿真基线。当前工程提供可运行交互系统、结构化配置、PostgreSQL/TimescaleDB脚本、测试、部署配置和完整文档体系。

## 已实现

- 09:00—09:47的15个关键事件节点；
- 播放、暂停、重置、0.5—10倍速和任意时刻跳转；
- 以所提供总体布局图为连续底图，同屏显示3F候车层、2F站台层和1F出站层；
- 37,000人守恒客流、聚合旅客点和四级密度；
- 疏散、分流、退票、高普联动、回流等路径的动态方向连线；
- 39个闸机、广播、大屏、疏散门和疏散指示标准化图标及实时状态；
- 6个视频监控点位和可拖拽仿真监控悬浮窗，明确标注暂未接入真实视频流；
- 无滚动条总图视口，支持鼠标拖拽平移、放大、缩小和位置复位；
- 监控面板支持整组展开/收起，每个监控窗支持独立折叠；
- 总体布局底图扩大显示，隐藏连线说明文字与原图底部图标说明区；
- 数据库快照、指标、设备日志、一致性、追溯与变更模型；
- 自动化构建、数据测试和版本同步门禁。

## 快速启动

```bash
npm ci
npm test
npm run dev
```

## 工程结构

```text
app/                 页面与全局视觉
components/          仿真工作台和站区视图
lib/                 时间线、客流与设备状态逻辑
data/                场景、区域、设备和路径配置
database/            PostgreSQL/TimescaleDB结构与种子
docs/                需求、架构、算法、部署、操作、测试、版本和研究计划
scripts/             构建与版本同步校验
tests/               自动化数据与结构测试
.openai/hosting.json 部署配置
```

## 质量门禁

`npm run verify:sync` 校验版本、核心文档、事件、客流和设备数量；`npm test` 在同步校验后执行生产构建与测试。任何需求或设计变更都必须同步更新代码、数据、测试、追溯矩阵、文档和变更记录。

## 当前边界

这是业务逻辑和交互的第一阶段高保真验证基线，不是最终Unity Windows可执行程序。真实视频融合、CAD/BIM坐标、音频、微观A*、DOTS/ECS、40,000个体性能与48小时稳定性需在补齐外部数据和生产环境后实施。详见 `docs/01_需求基线与范围.md`。
