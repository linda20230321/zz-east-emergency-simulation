# 郑州东站应急疏散高保真仿真系统

版本：0.8.0

基于水害导致北京方向列车大面积晚点、旅客滞留疏散演练脚本构建的数据驱动仿真基线。当前工程提供可运行交互系统、结构化配置、PostgreSQL/TimescaleDB脚本、测试、部署配置和完整文档体系。

## 已实现

- 09:00—09:47的15个关键事件节点；
- 播放、暂停、重置、0.5—10倍速和任意时刻跳转；
- 以所提供总体布局图为内容蓝本完成深色高清重绘，同屏显示3F候车层、2F站台层和1F出站层，移除图内标题且保留页面顶部标题；
- 37,000人守恒客流、彩色聚合旅客圆点和四级密度，Web端不显示网格、椭圆、多边形或密度文字等冗余底层图表；
- 底图采用上北、下南、左西、右东的统一方向基准，正南、正北、西南、西北四个出口在图上明确标识；
- 从候车室到西广场同时生成四条候选疏散路线，使用融合曼哈顿距离、客流密度、路径长度和转向代价的改进型A*逐帧重算并切换推荐；
- 保留闸机、广播、信息屏、通道、窗口及6个监控点，按位置、状态、责任岗位和脚本节点映射；
- 广播与导向内容使用脚本文案，气泡可关闭、重开并由用户点击触发语音；
- 当前节点同步呈现处置流程、岗位职责、设备操作和信息内容，09:35内部按G806、G1808、G51三轮放行继续细分；
- 顶部动态数字看板同步展示全站客流、10分钟站内积压预判、实时积压、西广场承接、晚点/停运列车和激活设备，支持数值平滑刷新、变化量及趋势线；
- 基于统一Agent快照在CPU端计算KDE密度并保留Unity Shader接口；Web端以绿色、黄色、橙色、红色人员圆点表达密度；
- 人员圆点限制在各区域的百分比显示范围内，主图、动态路线、区域人数、CPU KDE和六路监控共同读取同一数据源；
- 3F、2F、1F固定位置显示本层实时总人数；G806、G1808、G51开始检票下站台时显示车次、站台和乘车人数；
- 6个视频监控点位和可拖拽仿真监控悬浮窗，与底图人员位置、路线推荐和仿真时刻同步，明确标注暂未接入真实视频流；
- 无滚动条总图视口，支持鼠标拖拽平移、放大、缩小和位置复位；
- 监控面板支持整组展开/收起，每个监控窗支持独立折叠；
- 总体布局底图采用1842×3414高清资源，支持100%完整呈现、平滑滚轮缩放和任意方向拖拽；
- 数据库快照、指标、设备日志、一致性、追溯与变更模型；
- 自动化构建、数据测试和版本同步门禁。

## 工程结构

```text
app/                 页面与全局视觉
components/          仿真工作台和站区视图
lib/                 时间线、客流与设备状态逻辑
data/                场景、区域、设备和路径配置
database/            PostgreSQL/TimescaleDB结构与种子
unity/               Unity CPU KDE控制器、热力Shader及接入说明
docs/                需求、架构、算法、部署、操作、测试、版本和研究计划
scripts/             构建与版本同步校验
tests/               自动化数据与结构测试
.openai/hosting.json 部署配置
```

## 质量门禁

`npm run verify:sync` 校验版本、核心文档、事件、客流和设备数量；`npm test` 在同步校验后执行生产构建与测试。任何需求或设计变更都必须同步更新代码、数据、测试、追溯矩阵、文档和变更记录。

## 当前边界

这是业务逻辑和交互的第一阶段高保真验证基线，不是最终Unity Windows可执行程序。当前改进型A*运行在归一化站区网络上；真实视频融合、CAD/BIM精确坐标、音频、DOTS/ECS、40,000个体性能与48小时稳定性仍需在补齐外部数据和生产环境后实施。详见 `docs/01_需求基线与范围.md`。
